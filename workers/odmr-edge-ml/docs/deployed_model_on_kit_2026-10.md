# The deployed scalar model on the kit: recipe, chain and accuracy (2026-10-14)

One chain for the deployed model `fcnn_v2_residual_dataset_a`: committed dataset recipe → float checkpoint → INT8 TFLite → `.vnnx` → VectorBlox simulator → PolarFire SoC Icicle Kit (V250 NPU), with errors in microtesla against the dataset labels at every stage. Everything below was run on 2026-10-14; the commands, hashes and outputs are in this repository (`scripts/`, `experiments/`, `checkpoints/`, `exports/`) and in the kit repository's `evidence/2026-10-14-deployed-fcnn/`.

## Model contract

The deployed model is a two-channel residual model, not an absolute-field estimator:

- input `[1, 1, 100, 2]` (NHWC): channel 0 the normalized spectrum, channel 1 a Gaussian anchor centred on the PID lock-point;
- output: ΔB = |B_true| − B_PID in µT (one value);
- deployed field: B_PID + clip(ΔB, ±2.25 µT).

Preprocessing, quantization (input scale 0.007843137718737125, zero point −1; output scale 0.022874947637319565, zero point 1) and the clamp are the functions of `experiments/fcnn_v2_int8_float_equivalence.py`, imported by `experiments/deployed_model_on_kit.py`; nothing was re-implemented. Artifacts: `exports/fcnn_v2_residual_dataset_a_int8.tflite` (7,656 bytes, sha256 `e3b55da96ee633a58109007d4244304e2ad4a22853b10335fa41879e815b5371`), float checkpoint `checkpoints/best_model_dataset_a.pt` (58,165 bytes, sha256 `e0c314265017a999cd57c2b0c168c2d3dc229c9edbb3c630887ffb94ff57ed0a`).

## Pass criteria, set before the run

1. float vs INT8-CPU residual: max |Δ| ≤ 5 µT and MAE ≤ 0.5 µT;
2. INT8-CPU vs VectorBlox simulator: 0 LSB;
3. simulator vs kit: 0 LSB;
4. kit final-field MAE ≤ float final-field MAE + 0.2 µT, both against the label, PID-only MAE beside them.

A failed stage stops the chain and is reported as failed.

## Run

Inputs: rows 0–511 of the original test split (its md5 is recomputed and checked by the script). Prepared with `experiments/deployed_model_on_kit.py --prepare --out .scratch/kit-run-2026-10-14` (TensorFlow/`tflite_runtime` environment needed for the INT8 CPU run). The pfkit payload is the same array in NCHW element order, `[512, 2, 1, 100]` int8 (sha256 `69292f3987457dfe…`), because the VectorBlox simulator and the kit runner take model-order input.

Chain (pfkit from `polarfire-agent-skills`, tools host = Beelink WSL `vbx-env`, V250):

```bash
pfkit inspect model.tflite --run-dir R
pfkit compile model.tflite --output R/model.vnnx --config ~/.config/pfkit/toolshost.yaml --run-dir R
pfkit sim R/model.vnnx --input R/input.int8.npy --output R/sim.npz --config ~/.config/pfkit/toolshost.yaml --run-dir R
pfkit infer R/model.vnnx --input R/input.int8.npy --output R/hw.bin --json R/hw.json --config ~/.config/pfkit/kit-private.yaml --run-dir R
PYTHONPATH=src python3 experiments/deployed_model_on_kit.py --evaluate --run .scratch/kit-run-2026-10-14
```

Compile: `model.vnnx` 12,832 bytes, sha256 `55bf88b72725c7b252ab48107436cd31427fb86da81a207fc19ab0afad06f5b9` (tools host `vbx` 2.0.0, `vnnx_compile -c V250`). The June 2026 bring-up compiled the same TFLite to a 12,832-byte `.vnnx` with sha256 `6c5cd21a…` on the SDK 2.0.3 bring-up toolchain (polarfire-hybrid-control DLOG-048): same size, different bytes, so the compiler build differs between the two dates. The new file is bit-exact against the INT8 TFLite on the simulator and on the kit (criteria 2 and 3), which is the check that matters.

Kit: image with overlay `vbx_only`, node `vbx@60030000`; `vbx_run` completed 512 of 512, `npu_error 0`, `exit_code 0`.

- INT8-CPU vs simulator: 0 LSB. Simulator vs kit: 0 LSB.
- float vs INT8 residual: max 0.7033 µT, MAE 0.0314 µT.
- Kit latency per sample (NPU start to poll, quiet board): median 0.038 ms, p90 0.038 ms, max 0.069 ms.
- All four criteria PASS. Chain: PASS.

Reading: on these 512 held-out rows the kit's final field is 4.83 % better than PID alone (14.474 against 15.209 µT), against the 4.90 % reported on the full 5,000-row split in `experiments/fcnn_v2_int8_float_equivalence_2026-06-21.md`; the kit output equals the INT8 TFLite output bit for bit. The absolute error stays large (14–15 µT on 20–70 µT fields) because the model corrects at most ±2.25 µT per step; the oracle ceiling for that clamp is 9.35 % (`experiments/fcnn_v2_clamp_oracle_ceiling_2026-10-12.md`). Synthetic data; no live diamond.
