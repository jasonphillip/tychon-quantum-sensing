# Dataset Manifest Contract

Every generated dataset MUST include a manifest with the following fields. This contract defines what downstream ML consumers expect from the simulator.

## Required Manifest Fields

### Provenance
- `generator_git_sha` — Git SHA of the generator code
- `config_hash` — Hash of the simulation config used
- `simos_version` — SimOS version string
- `qutip_version` — QuTiP version string
- `backend` — Backend used (e.g. "qutip", "numpy")
- `generated_at` — ISO 8601 timestamp

### Random Seeds
- `master_seed` — Master random seed
- `train_seeds` — Per-spectrum seeds for training split
- `val_seeds` — Per-spectrum seeds for validation split
- `test_seeds` — Per-spectrum seeds for test split

### Split Definitions
- `n_spectra_train`, `n_spectra_val`, `n_spectra_test` — Split sizes
- `train_indices`, `val_indices`, `test_indices` — Index lists

### Spectral Resolution
- `n_freq_points` — Frequency points per spectrum
- `freq_range_Hz` — Sweep range (start, stop) in Hz

### Corruption Parameter Ranges (Train/Val)
- `p1_concentration_range_ppm` — P1 concentration range in ppm
- `temperature_range_K` — Temperature range in Kelvin
- `b1_gradient_range` — B1 gradient fraction range
- `b_perp_range_T` — Transverse field range in Tesla

### Anti-Inverse-Crime: Test-Specific Ranges
- `inverse_crime_shift` — Boolean flag: whether test-split distributions are shifted
- `test_p1_concentration_range_ppm` — Test P1 range (null when same as train)
- `test_temperature_range_K` — Test temperature range (null when same as train)
- `test_b1_gradient_range` — Test B1 gradient range (null when same as train)
- `test_b_perp_range_T` — Test transverse field range (null when same as train)

When `inverse_crime_shift` is true, the test split draws corruption parameters from
shifted distributions (default: mean +12.5%, width +20%) so the model is evaluated
on out-of-training-distribution conditions. This prevents the "inverse crime" where
train and test data share identical generative distributions.

Callers can also supply explicit test ranges for full control (e.g., to shift only
temperature while keeping P1 the same).

### Vector-Readiness (Path-Agnostic Bias Configuration)

For datasets generated in the bias-amplified regime where all four NV crystallographic
axes are spectrally resolved (Phase-II vector readout):

- `multi_axis_mode` — When `true`, spectra were generated by ensemble-averaging the
  four NV axes' per-axis SimOS spectra. At zero bias the four axes degenerate to the
  legacy single-axis lineshape, so `multi_axis_mode=false` (default) is fully
  backwards-compatible with v3-era scalar datasets.
- `bias_B0_T` — Nominal bias-field magnitude in Tesla (hardware setpoint, not the
  per-spectrum draw). Default `0.0` reproduces the legacy scalar regime.
- `bias_direction_uvw` — Bias-field unit vector in the lab frame. Default `(0, 0, 1)`.
- `bias_B0_range_T` — Per-spectrum bias-magnitude sampling range in Tesla, or `null`
  for fixed magnitude. In `multi_axis_mode` the actual per-spectrum `B_lab` is drawn
  isotropically with magnitude from this range; the resulting `|B_lab|` is recorded
  in the per-spectrum `labels` array.
- `concentrator_amplification` — Path B (flux concentrator) passive amplification
  factor. Default `1.0` indicates no concentrator (Path A or no-bias regime).
- `magnet_drift_ppm_per_K` — Path A (permanent magnet) thermal drift coefficient in
  ppm/K. Default `0.0` indicates no thermal drift modeling (Path B or no-bias).

The simulator-side schema is **path-agnostic**: a single dataset describes either
Path A (permanent magnet) or Path B (flux concentrator) hardware, with the
`concentrator_amplification` and `magnet_drift_ppm_per_K` fields identifying which.
Downstream BLUE projection on the 8-resonance residual vector is identical for both.

The 8x3 NV-axis projection matrix used by downstream vector inversion is fixed by the
diamond crystal lattice — see `nv_geometry_matrix()` in `src/nv_sensor_sim/physics/lineshape.py`.

### Units
- `units` — Dictionary mapping quantity names to SI unit strings

### Time-Series (Sequence) Datasets

A time-series ("dynamic") dataset is produced by `scripts/generate_sequence_dataset.py`
(`pipelines/sequence_generate.py`). The magnetic field sweeps over `n_timesteps` frames so the
NV-axis resonances move and cross in frequency space, with per-frame collision labels. Frames
are rendered by the 4-axis lineshape path reused from the static vector pipeline.

- `contract_version` — shared data-contract version tag; `"v1"` for these time-series datasets
  (empty on legacy/static manifests). Additive: consumers accept it when present.
- `sequence_mode` — `true` for a time-series dataset; default `false` (static single-frame), so
  existing static manifests load unchanged. This is the flag downstream consumers branch on:
  static `/{split}/spectra` is `(N, F)`, sequence is `(N, T, F)`.
- `n_timesteps` — number of frames T per sequence.
- `dt_s` — time between frames in seconds (sets the per-line df/dB slope and the loss-of-lock
  Γ/2-per-cycle comparison).
- `n_lines` — number of resonances L: 8 electronic (4 axes × 2 transitions), or 24 with the
  ¹⁴N hyperfine triplet.
- `hyperfine` — whether the ¹⁴N hyperfine triplet is modeled. Default `false` (L=8). **L=24 is
  not yet produced** (see the forward note in the HDF5 layout below).
- `linewidth_Hz` — Γ (FWHM in Hz) from `compute_linewidth(p1)`, used for collision labelling.
- `linewidth_rendered_Hz`, `mw_saturation_s0` — the *rendered* lines are power-broadened:
  Γ_rendered = Γ · √(1 + s0·mw_scale²) (≈4.9% wider at s0 = 0.1, mw_scale = 1). Collision
  labels deliberately keep the intrinsic `linewidth_Hz` (v0 convention).
- `collision_threshold_linewidths` — k in the `|f_i − f_j| < k·Γ` collision rule. The rule
  runs over **all** line pairs, including the two transitions of the same axis (an axis'
  own ± pair collides when its splitting drops below k·Γ).
- `bias_B0_T`, `bias_direction_uvw` — the static bias (reused from the vector config). The
  lab-frame bias vector is `bias_B0_T · normalize(bias_direction_uvw)`; the repo convention
  aligns the crystal [uvw] axes with lab xyz, so the `_uvw` direction is also the lab direction.
- `sweep_description` — free-text description of the field sweep.
- Structured sweep geometry (additive; prose stays in `sweep_description`): `sweep_mode`
  (`"fixed"` = one configured ramp for every sequence; `"isotropic"` = per-sequence held
  ramp with direction uniform on the sphere), `sweep_scalar_range_T` /
  `min_sweep_delta_T` / `min_ramp_window_frac` / `min_axis_projection_T` (isotropic
  parameters: independent endpoint scalars, minimum motion, minimum ramp sub-interval,
  projection-zero rejection floor), `ramp_start_T` / `ramp_end_T` (fixed-mode endpoints),
  `jitter_frac`, and `n_ramp_resamples` (geometries rejected by the projection guard).
- `sequence_stats` — per-split label statistics computed at generation time: crossing
  counts per sequence (a *crossing* = two lines swapping frequency order, vs a *collision*
  = within k·Γ), no-crossing fraction, crossing-frame spread, collision-frame fraction,
  collision dwell-length distribution, min same-axis splitting + near-merge fraction
  (splitting < 2Γ), min per-axis |B·n|, max line speed, and the split's ramp-resample count.
- Per-axis contrast asymmetry: `axis_contrast_scale` — per-axis MW Rabi-amplitude factors
  (the MW polarization projects differently onto each NV axis; contrast follows via
  saturation C ∝ s/(1+s), and weaker-driven axes render slightly narrower). This is a
  **deployment prior** — fixed MW antenna geometry → fixed axis ordering — with the same
  status as the fixed bias direction. Identical contrast is the maximally-ambiguous
  association case; per-axis contrast is a real, usable identity cue (arXiv:2507.00215)
  available to trackers and classical baselines alike. `axis_contrast_drift_std` /
  `axis_contrast_drift_tau_frames` describe the optional slow per-sequence AR(1) drift of
  those factors (None = static). `line_depths` records the reference per-line dip depths
  (geometry-matrix order, averaged-spectrum units) at the bias-only field with nominal
  scales.
- Trajectory-family mixture (isotropic sweeps): `trajectory_family_weights` — normalized
  per-sequence mixture over `held` (hold–ramp–hold), `reversal` (ramp out, turn around at
  a uniform-random frame in `reversal_turn_frac_range`, ramp back at a generally
  different rate — field velocity crosses zero, the velocity-ambiguous tracking case),
  and `ou` (held ramp plus a seeded OU field perturbation with std `field_ou_sigma_T`
  and correlation time `field_ou_tau_frames`). Per-sequence family assignments, reversal
  turn frames, reversals-inside-collision-dwell counts, per-family stratified summaries,
  and achieved OU wander live in `sequence_stats`. The min-projection guard and the
  window-containment asserts apply to every family.
- `numpy_version` — recorded alongside `simos_version`/`qutip_version`: per-sequence seed
  streams depend on numpy's `Generator` implementation.
- `freq_range_Hz` may be **pinned** in the generator config to hold the grid fixed across
  lineages (v1 pins v0's exact window/F). Generation fails fast if the derived worst-case
  window does not fit inside the pin, and asserts post-render that every stored label lies
  within the window.

All sequence quantities are SI: frequencies in Hz, fields in Tesla, time in seconds. The
`resonance_frequency` and `linewidth` unit strings are added to `units`.

## Train/Test Data Separation Protocol

**Two-layer separation:**

1. **Seed separation (always enforced):** Train, val, and test splits use pairwise
   disjoint random seeds. Enforced at generation time (`replace=False`) and validated
   by `DatasetManifest.validate()`, which raises `ValueError` on any overlap.

2. **Distribution separation (opt-in):** When `shift_test_ranges=True` is passed to
   `generate_dataset()`, or when explicit `test_*_range` parameters are provided, the
   test split samples corruption parameters from shifted distributions. The manifest
   records the exact test ranges used.

Default behavior (backward compatible): all splits share the same parameter ranges;
only seeds differ.

## File Format

- HDF5 (`.h5`) with JSON sidecar manifest, OR
- Numpy compressed (`.npz`) per split with JSON sidecar manifest

### HDF5 Layout

```
/{split}/spectra          — shape (N, n_freq_points)
/{split}/frequencies      — shape (n_freq_points,)
/{split}/labels           — shape (N, 3)  [B-field vector ground truth]
/{split}/corruption_params — shape (N, 4)  [p1, T, b1_grad, b_perp]
/{split}/seeds            — shape (N,)    [per-spectrum seeds]
```

### HDF5 Layout — Time-Series (Sequence) Datasets

When `sequence_mode` is `true` each split group holds the per-frame time-series instead of the
static arrays above (N = sequences, T = `n_timesteps`, F = `n_freq_points`, L = `n_lines`):

```
/{split}/spectra          — float32 (N, T, F)   normalized PL time-series (≈1 off-resonance)
/{split}/frequencies      — float32 (F,)        MW frequency axis (Hz)
/{split}/B_true           — float32 (N, T, 3)   ground-truth lab-frame B (Tesla) per frame
/{split}/resonance_freqs  — float32 (N, T, L)   center frequency (Hz) of each line per frame
/{split}/line_axis        — int8    (N, T, L)   NV axis id 0–3 (association ground truth)
/{split}/line_transition  — int8    (N, T, L)   transition id (0 = ms0→−1, 1 = ms0→+1)
/{split}/collision_mask   — bool    (N, T)      True where any two lines are within k·Γ
/{split}/line_collision   — bool    (N, T, L)   True for each line within k·Γ of another
/{split}/seeds            — int64   (N,)        per-sequence seed
/bias                     — float32 (3,)        static bias vector (Tesla), top-level
```

**Line ordering and identity.** Resonance index ℓ matches `nv_geometry_matrix()` row ℓ:
`axis_id = ℓ // 2`; even ℓ is the `+n_i` row (s = +1, ms0→+1, `line_transition = 1`), odd ℓ is
`−n_i` (s = −1, ms0→−1, `line_transition = 0`). `resonance_freqs` are the **diagonalized** line
centers — the true dip positions — so each label sits on its dip in `spectra`. First-order
analytic centers (`D + s·γ·(B·n_i)`) are **deliberately NOT used**: a transverse field adds a
second-order common-mode shift to both transitions of an axis (≈6.8 MHz at 5 mT‖z, up to ≈24 MHz
off-axis — **3–16·Γ even in the few-mT regime**), so first-order labels would sit many
linewidths off the real dips.

**Consumer guidance.**

- *Reconstruction from observed lines* (what a tracker/baseline does from `spectra`): recover each
  axis projection `B·n_i` from the **splitting** `(f₊ − f₋)/2 ≈ γ·(B·n_i)`, **not** from an
  absolute center (`f − D`). The large common-mode shift (up to ≈9·Γ here) cancels **exactly** in
  the splitting; a smaller second-order **asymmetric** residual remains (**≲ 0.4·Γ, a few hundred
  kHz** at the few-mT extremes — measured 0.35·Γ max on `sequence_sanity_v0`). So the splitting is
  **first-order accurate, not exact** — but it is ~25× closer than an absolute center, and is what
  feeds the BLUE A-matrix (`nv_geometry_matrix()`).
- *Exact ground-truth projection* (for labels / metrics, not from the spectrum): use `B_true·n_i`
  directly — `B_true` is the stored lab-frame field, so the exact per-axis projection needs no
  spectral reconstruction. Use this for scoring; use the splitting only for what the model observes.
- *Fixtures*: any synthetic fixtures must include the second-order common-mode center shift, so a
  tracker/baseline develops against realistic centers rather than first-order ones.
- *Measurement noise*: stored spectra are deliberately **noiseless** (deterministic renders).
  Apply photon shot noise consumer-side with `nv_sensor_sim.physics.shot_noise` —
  `apply_shot_noise(spectrum, photons_per_point, seed)` for train-time augmentation
  (per-epoch seeds) and fixed-seed evaluation realizations; `photons_for_dip_snr` sizes the
  photon budget against the faintest line (`min(manifest["line_depths"])`). The model is
  Poisson counting on the normalized PL: `sigma(f) = sqrt(S(f) / N)`.

**`line_collision` and `seeds`** extend the orchestrator's initial contract (the shared
time-series contract is **v1**): the per-frame `collision_mask` alone cannot tell the association
head *which* lines are crossing, and the per-sequence `seeds` preserve this repo's
reproducibility / seed-separation discipline.

> **Hyperfine (L=24) forward note.** With `hyperfine=true` the 24 lines are 8 electronic × 3
> ¹⁴N components, but `line_axis` (0–3) × `line_transition` (0/1) yields only 8 unique keys. A
> per-component `line_mI` (N, T, L) field is needed to uniquely key the 24 lines; this is
> deferred (v0 ships L=8). Coordinate with `odmr-vector-tracking` before enabling hyperfine.

### Optional keys — dwell lineage

The dwell-sweep eval lineage (`sequence_dwell_v1` / `sequence_dwell_v1_cues`) adds
**backward-compatible, optional** manifest keys and per-sequence HDF5 arrays. All are `null`/absent
on every prior lineage, which therefore loads unchanged, and **the L=8 line contract is unchanged**
(no new lines, same `resonance_freqs` / `line_axis` / `line_transition` shapes and semantics). With
both physics knobs off, generation is byte-identical to the same call without them.

**Manifest keys.**
- `sweep_mode: "dwell"` — held-template merged-dwell sweep (vs `"fixed"`/`"isotropic"`).
- `axis_offsets_hz` — per-axis static strain / E-field ZFS offset ladder (length 4, Hz), or `null`
  (off). **Common-mode per orientation**: both the ms0→+1 and ms0→−1 transitions of axis *i* shift
  by `axis_offsets_hz[i]`, so the per-axis line **center** `(f₊ + f₋)/2` moves but the **split**
  `(f₊ − f₋)` is preserved. **Sign convention**: a positive value shifts that orientation's ZFS
  **up** (both transitions together). **Interaction with the splitting-based decode**: because the
  split is invariant, a decoder that recovers `B·nᵢ` from `(f₊ − f₋)/2` (the standard path, see
  "Consumer guidance") is **blind** to this offset — it is a *static, center-only* identity
  fingerprint, invisible per-frame at kHz scale but recoverable by integrating a long merged dwell.
  It flows into the `resonance_freqs` ground truth automatically. Default cues value = the Meneses
  et al. real-device fit `(19.6, −4.2, −3.5, −11.9) kHz` (arXiv:2502.14683 as cited in the issuing
  dispatch). *Caveat:* arXiv:2502.14683 has a **title collision** with an object-tracking paper
  (flagged in the 2026-07-02 TVW optimization-levers memo, Tier 4); the *values* are used as the
  per-axis M_z strain ladder — the physics (a per-orientation axial-strain ZFS shift) is standard NV
  and independent of the exact citation number. *Label precision note*: `resonance_freqs` is float32
  at ~2.87 GHz (~256 Hz quantization), so the kHz offsets are represented coarsely but adequately;
  the per-line integer identity labels are exact.
- `nv_density_ppm` — NV(−) concentration (ppm) driving the **NV–NV cross-relaxation** PL feature, or
  `null`/`0` (off). At an inter-orientation degeneracy `|B·nᵢ| = |B·nⱼ|` (Espinós & Budker
  arXiv:2512.13835 Eq. 3 — the same condition that forces the merge here) dipolar flip-flops
  depopulate ms=0 and reduce PL. Modeled as extra Lorentzian PL dips at the (near-)degenerate
  transition frequencies (Espinós Eq. 8 phenomenological form), gated by a Lorentzian in the
  field detuning `‖B·nᵢ| − |B·nⱼ‖` of density-dependent FWHM, amplitude density-dependent — a
  two-point power-law fit to Dhungel et al. arXiv:2301.09666 (3.8 ppm → 0.78 mT / ~1.79 %;
  16 ppm → 1.42 mT / 3.95 %; visible ≳0.9 ppm, contrast 0 below that floor). **Modeling choices**
  (`nv_sensor_sim.physics.cross_relaxation`): the sources measure the MW-free feature as PL-vs-field;
  we render it as extra dips in the MW-swept CW-ODMR frame; the field-detuning width gates *how
  strongly / which frames*, while each dip's *spectral* width is the ODMR linewidth Γ. The feature
  **modifies the spectrum only** — it does **not** add lines to `resonance_freqs`. Its value is
  realism + a physics-anchored merge marker; identity value is measured downstream, not asserted.
  Default cues value = 3.8 ppm (the Dhungel calibration point; deployment-relevant density depends on
  the diamond spec).
- `data_md5` — reproducible md5 over the dataset arrays (dtype+shape+bytes, key-sorted; independent
  of HDF5 container timestamps), so same-seed regeneration hashes identically.
- `sequence_stats["test"]["dwell_config"]` / `["dwell_buckets"]` — the merge templates, dwell/topology
  bucket layout, realized-dwell summaries, and the mirror-pair note (below).

**Per-sequence HDF5 arrays** (each shape `(N,)`, under the split group):
```
exit_topology        int8   0 = cross (lines swap), 1 = bounce (return to entry sides)
dwell_frames         int32  realized merged-dwell length (contiguous frames with |f_p−f_q| < Γ)
dwell_frames_target  int32  requested D ∈ {8,16,32,64,128,192}
merge_p, merge_q     int8   the target coalescing line pair (geometry-matrix indices)
mirror_p, mirror_q   int8   its NV-symmetry mirror pair (p^1, q^1)
approach_sign        int8   which side of a_merge the ramp approaches from (±1)
template_idx         int8   merge-template index within this dataset's enumerated set
```

> **Mirror-pair note (physics-forced structure).** A **single-pair** cross-axis merge is
> **physically impossible** in the noiseless L=8 model. The per-axis rendered spectrum depends only
> on `(|B·nᵢ|, B⊥,ᵢ)`; at any cross-axis frequency degeneracy `f_p = f_q` the condition forces
> `|B·nᵢ| = |B·nⱼ|`, hence `B⊥,ᵢ = B⊥,ⱼ`, hence identical per-axis Hamiltonians — so the **mirror
> pair** `(p^1, q^1)` coalesces **exactly and simultaneously** at the reflected frequency (verified:
> mirror separation = 0.000 MHz; a full field scan finds no window where it resolves). This is the
> same `|B·nᵢ|=|B·nⱼ|` condition as the cross-relaxation feature. So each dwell sequence realizes
> **one target coalescing pair + its mirror** (a coalescing quartet) with the **four spectator
> lines** separation-protected — not the six a naive single-pair reading would imply. This deviation
> from the issuing dispatch's "one pair / six protected" is inherent to NV C3v symmetry, not a
> generator choice.

### Optional keys — widened-envelope lineage (v3, angle-stratified)

The angular field-coverage training lineage (`sequence_train_v3`) and its field-cone eval
(`sequence_eval_fieldcone_v1`) add **backward-compatible, optional** manifest keys and per-sequence
HDF5 arrays. All are `null`/absent on every prior lineage, and the **L=8 line contract is unchanged**.

**Why v3 exists.** `odmr-vector-tracking` increment-5 measured a deterministic field-acquisition
failure: the learned tracker loses field lock **216/216** on cross-axis merge pairs **(0,2)/(4,6)**,
which force **B to 41.5°/53.2° off-bias at 3.9/3.3 mT** — outside the v1/v2 training cone (≤ ~18°
off-bias). v3 widens the trained off-bias cone to **≥ 60°** (so 53.2° sits in the interior) and lowers
the **|B| floor to 3.0 mT**, on the same v1 contract (pinned 951-pt grid, same bias/contrast/Γ, T=256,
noiseless).

**Angle-stratified widening (`sweep_mode: "isotropic_widened"`).** Uniform isotropic sampling cannot
reach the wide cone at the pinned grid: the reachable off-bias angle is bounded by
`arcsin(|ext|/|bias|)` and the high-angle band is a measure-zero sliver near the floor (measured 0/1500
≥ 53° at ±4.5 mT). v3 instead samples the **off-bias angle directly** — a **training density change**
recorded in `stratification_law`. Two sub-populations:
- **angle-stratified** (majority) — off-bias angle `~ U[0, offbias_angle_target_deg]`, magnitude drawn
  from the `field_range_T` law, constructed at that stratum with random azimuth; the v1-style
  `held`/`reversal`/`ou` families set the ramp shape.
- **directed** (`directed_fraction`) — v1-style pass-through crossings aimed exactly at the cross-axis
  merge degeneracies (reusing the dwell `merge_direction`/`a_merge` machinery), covering (0,2)/(4,6).

**Cold-start diversity.** The failure is off-cone *acquisition*, not lock-carrying. A
`cold_start_fraction` of the angle-stratified sequences **start frame-0 at their drawn (possibly wide)
stratum** (cold acquisition); the rest carry a lock outward from the near-bias cone. Recorded per
sequence in `start_mode`.

**Three per-frame reject guards** keep every geometry physical and in-grid: the `min_field_T` |B|
floor (interior min), window containment (`window_margin_frac` below the pinned half-window), and the
existing `min_axis_projection_T`. In widened mode the config-time worst-case containment is skipped
(the per-frame guard + post-render label-containment assert are the backstop).

**Manifest keys (v3 train).** `sweep_mode: "isotropic_widened"`; `min_field_T`; `directed_fraction`;
`directed_approach_lw_range`; `offbias_angle_target_deg`; `window_margin_frac`; `data_md5`; and
`stratification_law` — a dict recording the off-bias-angle law, the |B| law, `cold_start_fraction`, the
carry parameters, and `directed_fraction` (the exact draw distribution, so increment-6 coverage
attribution is reproducible). `sequence_stats[split]["coverage"]` records realized off-bias-angle and
|B| distributions, `frac_ge_53_2`/`frac_ge_60`, sub-population and start-mode counts, and per-template
directed counts.

**Per-sequence HDF5 arrays (v3 train)** (each `(N,)`, under the split group):
```
sampling_family        int8   0 held, 1 reversal, 2 ou, 3 directed-held, 4 directed-reversal
max_offbias_angle_deg  float32 realized max off-bias angle over the trajectory (deg)
min_B_T                float32 realized min |B| over the trajectory (Tesla)
directed_template_idx  int8   merge-template index for directed sequences, -1 for angle-stratified
start_mode             int8   0 = acquire (cold start at stratum), 1 = carry, -1 = directed
```

**Field-cone eval (`sequence_eval_fieldcone_v1`, `sweep_mode: "fieldcone"`).** A held-out
(off-bias angle × |B|) ladder, eval-only (all `test`), that measures acquisition across and **beyond**
the v3 envelope. Buckets are `failure` (exact (0,2)/(4,6) merges), `control` (in-envelope), and
`beyond` (off-bias > the widened cone and/or |B| < 3.0 mT). The |B| floor and angle cap are **not**
enforced (beyond probes must exceed them); the min-projection + window guards do apply, and a
window-infeasible bucket is **stop-and-reported**. Per-sequence arrays: `bucket_class`
(0 failure/1 control/2 beyond), `target_angle_deg`, `target_B_mT`, `realized_max_offbias_angle_deg`,
`realized_min_B_T`, `merge_pair_p`/`merge_pair_q` (−1 off the failure buckets).
`sequence_stats["test"]["fieldcone_buckets"]` records the ladder.

Datasets live under `artifacts/datasets/<lineage>/` (gitignored). The HDF5 + JSON
manifest bundle is consumed by the downstream `odmr-edge-ml` (static) and
`odmr-vector-tracking` (time-series) training pipelines.

To regenerate a static lineage from scratch:

```bash
python scripts/generate_vector_dataset.py \
  --config configs/<lineage>.yaml \
  --output-dir artifacts/datasets/<lineage>/
```

To regenerate a time-series (sequence) lineage:

```bash
python scripts/generate_sequence_dataset.py \
  --config configs/<lineage>.yaml \
  --output-dir artifacts/datasets/<lineage>/
```
