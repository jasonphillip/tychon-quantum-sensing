## Reference Design Summary

### No .prjx — it's a Tcl-generated project
There's **no pre-built .prjx** to open. The project is built from scratch by running the master Tcl script with the `VECTORBLOX` flag:

```
MPFS_ICICLE_KIT_REFERENCE_DESIGN.tcl VECTORBLOX
```

This creates a project called `MPFS_ICICLE_Vectorblox` in a local directory.

### VectorBlox Configuration
- **core_vectorblox v1.1.12** — `PRESET:1` (this is the **V1000** preset, not V250)
- **M_AXI_DATA_WIDTH: 128** bits
- Clock: PF_CCC_C1 PLL generates **100 MHz (clk)** + **200 MHz (clk_2x)** from 50 MHz ref
- Includes `vectorblox_axi_resize` for width conversion
- Wrapped in `Vectorblox_ss` subsystem SmartDesign
- Connected to **FIC_0** via `COREAXI4INTERCONNECT`, DMA through **FIC_2**

### Architecture (VectorBlox variant)
```
MSS (MPFS250T_ES)
 ├─ FIC_0 → FIC0_INITIATOR (AXI4 xbar)
 │    ├─ Slave0: PF_SRAM (64KB)
 │    ├─ Slave1: DMA controller
 │    └─ Slave2: Vectorblox_ss (S_control)  ← CPU programs VBX here
 ├─ FIC_2 ← Vectorblox_ss (AXIM)           ← VBX DMA reads DDR
 ├─ FIC_1 → (peripherals)
 └─ FIC_3 → (IHC, GPIO, UART, PWM, I2C)
```

### Key Issue: PRESET:1 = V1000, not V250
The reference design uses `PRESET:1`. We need to verify what presets map to which sizes. For the MPFS250T fabric, V1000 may be too large. We need **V250** (`-c V250`).
