# V250-to-PID On-Kit Loop Evidence - 2026-06-21

## Summary

CONFIRMED on the Icicle kit: a Linux userspace helper now runs the V250 model, dequantizes `out[0]`, writes that value into M1 `u_ai`, pulses M0 `acc_start`, and streams M1 `post_clamp_out` / watchdog status back as CSV.

CONFIRMED follow-up: the helper now accepts per-row ODMR input CSV rows. The deployed dashboard path uses 120 held-out `production_50k_v2_aic` rows with normalized 100-point spectra plus learned-sigma PID-anchor channel, quantizes each row into the V250 input buffer, then feeds the per-row V250 output into the PID path.

CONFIRMED daemon follow-up: the same helper now supports `--daemon --state <path> --pid-file <path>`, so the Icicle can keep the V250->PID loop running persistently while the dashboard only starts, stops, and monitors it. This is still Linux userspace control, not FPGA-resident autonomous wiring.

## Key Finding

The first helper run cleared the watchdog during continuous V250 completions, but `post_clamp_out` still tracked plain `0.8 * error`. The cause was the M0 `inner_clamp_setpoint` at `0x60040020`: if left at zero, the HLS safety clamp accepts a zero-width AI sector and clamps `u_ai` to zero.

After writing `inner_clamp_setpoint = 0.045`, the actuator reflected the V250-derived negative correction:

```text
row 0: pid_only_out=0.160000, nn_u_ai=-0.046103, actuator_out=0.113892, watchdog_timeout=0
row 4: pid_only_out=0.163200, nn_u_ai=-0.046103, actuator_out=0.117096, watchdog_timeout=0
```

The `u_ai` magnitude is slightly above the 4.5% sector, so `clamp_active=1` is expected and safe.

After adding the CSV row loader, the deployed helper reports real per-row model input provenance:

```text
input_len=200 input_dtype=1 input_scale=0.007843018 input_zp=-1 input_source=odmr_v250_rows.csv input_rows=120
```

## 2 ms Watchdog Follow-Up

After the helper and daemon path were integrated, the dated two-slot 2 ms
watchdog image was built, exported, programmed, and checked on the kit. The
post-program dashboard evidence in
`libero/reports/2026-06-21-watchdog-2ms/` shows the same V250-loop behavior
against the programmed `WATCHDOG_TIMEOUT_CYCLES=250000` fabric image: the helper
keeps the watchdog clear while running, and the watchdog trips to safe fallback
after the helper is stopped.

The helper remains a Linux userspace bridge. It proves V250 output reaches the
PID actuator path and that the 2 ms watchdog supervises the helper, but it is
not FPGA-resident autonomous sensor-loop wiring.

## Safety Notes

- The helper maps only `0x60040000..0x60040fff`.
- It writes M0 limits/gains/inner-clamp/start and M1 error/u_ai.
- It reads actuator/watchdog/status from M1 only.
- It never touches `0x60001000`.
